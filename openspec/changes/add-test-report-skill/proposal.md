# Proposal: add-test-report-skill

## 意图（Intent）

当前团队在完成测试执行后，测试结果散落在终端输出、CI 日志或框架原生产物（JUnit XML、coverage 目录）中。痛点包括：测试结果需人工收集汇总、缺乏统一格式报告、失败用例上下文需人工回溯、质量指标无法沉淀为可追踪历史数据。

本变更新增一个 Skill，使 Agent 在执行测试后能够自动解析测试结果并生成结构化、可读性强的标准测试报告。一条指令即可完成"执行测试 → 收集结果 → 生成报告"全流程。

## 范围（Scope）

### 目标
- **G1**：一条指令（如"生成测试报告"）自动完成：执行测试 → 收集结果 → 生成报告。
- **G2**：报告内容标准化，包含摘要、明细、失败分析、覆盖率四大板块，章节顺序固定。
- **G3**：首期支持主流测试框架的结果解析（P0：Jest、Vitest 的 JSON reporter；pytest 的 JUnit XML / JSON report；JUnit XML 作为跨语言兜底）。
- **G4**：报告支持多种输出格式，默认 Markdown。

### 非目标（本期不做）
- 不做测试用例的自动生成或修复（仅报告）。
- 不做报告的在线托管 / Web 服务化展示。
- 不做多次运行结果的趋势对比分析（列为后续迭代候选）。
- 不做非测试类质量报告（如 lint、安全扫描）的聚合。
- 不做报告自动推送到 IM / 邮件等渠道。

## 受影响区域（Affected Areas）

| 区域 | 影响说明 |
|------|---------|
| Skill 定义 | 新增 `add-test-report-skill`，包含 SKILL.md 及解析器脚本、模板 |
| `openspec/changes/` | 本次变更产物目录 |
| `reports/` | 报告默认输出目录（运行时生成，非仓库跟踪） |
| 项目依赖 | 可能新增测试框架 devDependencies（Jest/Vitest）——但 Skill 本身不强制安装，仅在执行模式下探测 |

## 风险（Risk）

- **R1**：各框架 reporter 输出差异大，解析层需良好抽象。缓解：采用插件式解析器结构（NFR5），新增框架不影响既有解析器。
- **R2**：测试执行耗时不可控，长任务需交由后台执行并轮询。缓解：依赖 Agent 运行时后台任务能力，执行模式长任务降级为后台轮询。
- **R3**：当前项目（umi-mobile-app）尚未配置测试框架，执行模式可能无测试可跑。缓解：解析模式独立可用，支持已有结果文件。

## 滚动发布 / 回滚（Rollout / Rollback）

- **发布**：M1（P0）先行落地 Jest/Vitest JSON + JUnit XML 解析、Markdown 报告、执行/解析双模式；M2（P1）追加 pytest、覆盖率、fail_threshold；M3（P1）追加 HTML、JSON 伴随产物；M4（P2）后续迭代历史趋势、更多框架。
- **回滚**：Skill 为新增产物，无侵入式改动，回滚仅需移除 Skill 目录与 `reports/` 输出，不影响既有应用代码。
